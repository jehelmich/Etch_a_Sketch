What is actually running

Not a video of a demo, and not a reimplementation in JavaScript. The SystemVerilog for a Clarvi RV32I core, two quadrature decoders and a button scanner was translated to C++ by Verilator and compiled to WebAssembly. Your keypresses become quadrature transitions on the same pins the rotary encoders drive on the real board. The processor polls them, runs the same bare-metal C that runs on the FPGA, and writes pixels into a framebuffer that is copied to the canvas each frame.

The counter above is the simulated clock rate. The hardware runs at 50 MHz; in a browser you will see a fraction of that, which for something driven by a human hand is not noticeable.

Changing it

This page only lets you drive the device. To change it — the drawing code, the peripherals, the processor itself — clone the repository and build it; the same simulation runs natively, with waveforms and a test suite. 

git clone --recurse-submodules https://github.com/jehelmich/Etch_a_Sketch.git
cd Etch_a_Sketch
make -C sim test          # unit-test the peripherals
make -C software          # cross-compile the firmware
make -C sim run           # the same thing you are using now, natively
